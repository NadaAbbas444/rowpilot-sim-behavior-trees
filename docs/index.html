A greenhouse drone that flies without GPS, run by a behaviour tree.

rowpilot sweeps the dead-end lanes between crop rows: visual-inertial odometry tells it where it is, the depth camera keeps it centred in each lane, and a behaviour tree decides what to do next, from take-off to failsafes. Everything runs in simulation today, on the real drone's software chain.

Simulation

The real drone's software, in a simulated greenhouse

Not a toy model: the drone is the FireFly 2 from its CAD, its flight controller is ArduCopter, and its position comes from OpenVINS running on rendered camera images, exactly as on the hardware.

What is simulated

  • The FireFly 2 from its SolidWorks design: body, props, rotor positions, a D435i tilted 15° down, a Pi Camera Module 3 on the left.
  • A greenhouse with procedural tomato rows, rails and posts; dead-end lanes closed by an end wall.
  • GPS-denied flight: no GPS, no compass. OpenVINS → MAVLink odometry → ArduPilot EKF3.
  • A fast Python simulator too, for the tests and for trying ideas in seconds.

What the drone sees in a lane: the D435i infrared image (OpenVINS), the depth image (lane perception; blue near, red far), and the Pi Camera on the crop row.

Behaviour tree editor

Draw the mission. Run it. Watch every node.

A web editor for the behaviour tree: React Flow in the browser, a FastAPI server running the same tree code as the drone. Every node lights up as it runs and keeps its own log; a map draws the flight.

The full mission in the Python simulator at 20×: the running branch in amber, finished steps in green, the log and the map on the right.

Edit as a graph

Drag nodes from a palette, connect parent to child, set parameters. Children run top to bottom, as drawn. Impossible connections are refused as you draw.

Checked by the server

Unknown lanes, missing children, duplicate names, loose nodes: marked on the node as you edit. Run waits until the tree is right.

Live, from any point

Each run streams over a WebSocket: status changes, log lines, the pose every tick. Pages can join late or reconnect.

Two simulators, one button

From the editor straight into Gazebo

Choose Gazebo + ArduPilot + OpenVINS in the run settings and the same tree flies the full chain. The log then shows the flight stack next to the tree: ArduPilot's own messages, what the tree asks over MAVLink, EKF3 taking its position from the visual odometry, and OpenVINS initialising.

Five lanes flown in Gazebo from the editor (start-up at 2×, the flight at 8×): setup, VIO, EKF3, ArduPilot and MAVLink messages, then the tree's steps while the map draws the flight. All five lanes swept, 46–78 mm from the lane centre.

Lanes

The greenhouse is fixed. The tree chooses the lanes.

Lanes − 5 of 6 + in the toolbar: + adds the next lane with the mission's exact steps (go to the entry, align on the depth image, sweep in, turn round short of the end wall, sweep out, exit), − removes the last one with all its steps.

Each lane's entry comes from the greenhouse map; the depth camera then centres the drone in the lane, whatever the odometry drift.

Two lanes removed, one added back: the drone sweeps lanes 1–5 and goes home.

Start battery 45%: in lane 3 the guard fails and the failsafe flies home along the lane, never through the crop.

Failsafes

Safety first, every tick

A guard sits in front of the mission and is re-checked ten times a second. When a check fails, it interrupts whatever runs:

  • Battery at the reserve: fly back out of the dead-end lane, home, land.
  • Visual odometry lost briefly: hover and wait, then resume where the mission was.
  • Battery critical or odometry lost too long: land where it is.

Mission steps remember that they are done, so a pause never restarts the mission.

How it works

From camera pixels to motor commands

Who decides what: OpenVINS says where the drone is, the depth camera says where the lane centre is, the behaviour tree decides where to go, ArduCopter decides how to fly there.

Get started

Three levels, each adding to the last

Clone the repository, then go as far as you need. Full setup guide →

git clone https://github.com/NadaAbbas444/rowpilot-sim-behavior-trees.git
cd rowpilot-sim-behavior-trees && git checkout editor

1 · Python simulatorany OS, 5 minutes

python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,plot]"
python -m rowpilot run --out runs/nominal

2 · The editor+ Node.js 18

cd web && npm ci
npm run build && cd ..
python -m rowpilot editor
# http://127.0.0.1:8000

./scripts/setup_ardupilot_sim.sh
./scripts/run_ardupilot_sim.sh
